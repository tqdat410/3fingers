# Development

3fingers is a Manifest V3 Chrome extension. The runtime is plain JavaScript/CSS with no backend or runtime package dependencies.

## Setup

Use Node.js 22+ for the extension and PowerShell 7 for packaging. The independent website build uses Node.js 24.

```powershell
npm ci
npx playwright install chromium
npm run check
npm test
npm run test:browser
npm run release:pack
```

Load the `extension` directory at `chrome://extensions`. No build is needed. Reload the extension and its workspace after editing it.

The main extension page is `myfeeds.html`. The former `workspace.html` redirects there, and the extension action migrates a still-open legacy tab in place. Layout storage keys and panel IDs are unchanged. The JavaScript and stylesheet retain their `workspace` names.

User documentation is available in [English](user-guide.en.md) and [Vietnamese](user-guide.vi.md), with a [Vietnamese README](README.vi.md). The basic website lives in `website/` in this repository; see [website deployment](website-deployment.md) for the independent static build, tests and Cloudflare Pages setup. Extension packages exclude the website and its dependencies.

EN/VI messages live in `extension/_locales/en/messages.json` and `vi/messages.json`. `shared/i18n.js` uses the same catalogs for the saved English/Tiếng Việt choice through the EN/VI toggle beside tool theme; the initial automatic choice selects Vietnamese for Chrome's vi locale, otherwise English. Switching updates extension-owned text, status and accessible labels while preserving social documents. Chrome's manifest description uses its native locale resolution independently of the saved UI override. Language choice stays in local storage and adds no browser permissions. The development source version is 1.1.0; GitHub downloads continue to use the latest published Stable release until a new version is explicitly released.

Click the Chrome extension icon outside the workspace to focus an existing workspace or create one. Existing workspaces in the current window take priority; otherwise their Chrome window is focused. Loading workspace tabs are reused, and concurrent clicks share one open operation. Inside the workspace, the icon opens its control popup. The manifest has no default popup; the worker sets popup.html per workspace tab, clears it on navigation away and restores per-tab settings when it starts. The Go button reuses the same workspace-opening helper. The popup owns Reload all, tool theme, GitHub and adding sites; panel controls stay in the workspace. Popup commands are restricted to the extension's popup page, and the workspace rechecks permissions and the three-panel limit. No new browser permissions are required.

Each panel stores a boolean `pinned` preference, defaulting to false for existing workspaces. A solid pin excludes that panel in both directions at the scroll router without reconnecting its iframe. Global sync settings are retired and removed during normalization; unpinned panels participate unless the social requires native independent scrolling. TikTok and YouTube are always excluded as both source and follower, regardless of their stored pin preference. The authenticated ready handshake excludes them from scroll messages while permitting local mouse/pen dragging. Their solid pins cannot enable sync, but remain focusable for arrow-key reorder. Replacing either with another social resumes the stored user pin preference. Pinning affects scroll membership only, including when a panel is reloaded or switched to another site. Reddit uses the same pin-controlled synchronization as the Meta feeds. Facebook and Instagram /reel and /reels viewers are temporarily independent, based on the current frame route rather than the configured panel URL. Authenticated navigation updates both the background router and content policy; content discards queued movement while awaiting the matching route acknowledgement. The panel shows a disabled solid pin, without saving an automatic pin or reloading. Leaving the viewer restores the existing user pin preference and reading offsets. Inline videos and profile Reels grids do not change the policy; existing modal detection still pauses background scrolling for dialogs.

Social theme buttons activate native app controls. No adapter sets or retains root palette classes, dark attributes or color-scheme styles. `light`/`dark` remain transient commands; successful native ownership returns the panel to `site`. Workspace/archive normalization discards saved overrides from earlier builds, so reloading does not reapply an extension color preference. Read-only DOM and system-theme listeners update the toolbar when the app changes appearance. Missing or ambiguous controls fail closed without a color fallback. Native app preferences can be shared with its other panels/tabs. The independent `toolTheme` key affects extension surfaces only. Navigation reinjects against the exact document ID.

All seven social adapters run in the MAIN world through site-owned modules, mounted providers or native component methods in [social-theme.js](../extension/shared/social-theme.js). Instagram uses its persistent toggle rather than its visual-only setter. Threads uses its current provider setter. X calls its native palette engine, settings action and preference helper; it does not navigate to Display. TikTok follows its native explicit-selection sequence through the provider and the provider’s own cookie library, including the verified manual-selection flag. Loaded module signatures and current React providers are checked before any call; unknown or ambiguous signatures disable that site’s switch. A transient native failure retains the verified capability and allows retry. Native readiness runs outside the shared startup connection queue. Completion rechecks enabled pane identity and exact document ID before updating toolbar state; navigation discards obsolete results.

Browser tests use temporary profiles, a local server on port 49317 and intercepted social fixtures. They do not use your account or prove that every real social route works. Generated diagnostics stay local and are ignored by Git. Test teardown closes its browser/server and deletes the temporary profile; do not start another fixture on a different port when 49317 is already in use.

Earlier actual-site checks covered Reddit pagination/comments and YouTube playback, fullscreen and consecutive Shorts. Subsequent use reproduced a renderer crash on YouTube watch pages in the production workspace and Reddit CSRF failures, so those earlier checks do not establish long-session stability. The current YouTube scope is Shorts only. Run playback checks with the test tab visible: native sites can defer media and feed loading in background tabs.

## Privacy

X opens native Home at https://x.com/home?lang=. Its current Service Worker skips cached app-shell navigation when lang is present, letting the existing workspace-only header rule act on the network response. siteFrameUrl adds an empty lang only when missing, maps the bare root to /home and preserves other route/query/language/hash data. Stored panels, archives, frame loads and runtime history use this canonical URL; toolbar Back retains the parameter without duplicate history entries. Native SPA navigation is not intercepted. This depends on X implementation behavior and is not an official embedding API.

X uses the same fixed-site CSRF lifecycle as Reddit, with only ct0 on x.com. It participates in pin-controlled feed sync and local drag. A production-workspace check loaded 46 distinct posts over seven scroll cycles, with nine successful HomeTimeline requests, one successful TweetDetail and toolbar Back returning to Home. The measured reading requests had matching CSRF headers and transmitted cookies. This verifies that reading journey, not long-session stability. Settings, posting, messages and all secondary services are not guaranteed. Auxiliary api.x.com calls can still fail with 403/353. Research found that granting api.x.com caused token churn and broke timeline calls, so configure and permission changes disable only X with an actionable message if that host or a covering wildcard is already granted. Existing user grants are never removed automatically. Use Chrome’s extension site-access settings to return to narrow access, then Open the panel again.

Embedded-site checks established that Reddit and YouTube write their native theme preference cookies without a usable cross-site context. Reddit’s native preference saver now uses the existing single-owner cookie accessor for exact-name theme writes. YouTube’s PREF and TikTok’s three theme-cookie writes use a temporary command-local accessor, retained through asynchronous native effects and then removed. Only missing SameSite gains SameSite=None and Secure; native values, attributes and explicit SameSite remain unchanged. No auth-cookie policy or permission changes are involved. Reddit and YouTube reload only the affected exact document after saving; sibling panels are preserved and the replacement document gets a fresh native capability probe. These are private site APIs and may change with site updates.

Reddit’s embedded JavaScript can miss its SameSite=Strict csrf_token even when network requests include the cookie, causing native token/GraphQL HTTP 400 responses. The optional cookies permission is requested only on Open/select/add/restore of Reddit, together with its exact www and parent hosts. Parent-host access is needed for Chrome’s change events on .reddit.com cookies; it does not add another iframe-header rule. Existing Reddit panels without the new grant return to Open. Denial preserves the layout; revoking cookies or required site access removes Reddit frames while keeping peers and saved panel preferences.

The fixed-site worker bridge reads only csrf_token at https://www.reddit.com/ or ct0 at https://x.com/ using cookies.get, never enumeration, session/login cookies or cookie writes. After checking the workspace tab, direct frame, exact origin and current document ID, a MAIN-world document-local getter supplies only a missing CSRF value; nonempty native values win. CSRF and unrelated writes pass through; only the exact Reddit theme write receives the compatibility attributes described above. Cookie-change events refresh/remove the in-memory fallback; expired values are never supplied. Navigation binds a new document and cookies revocation removes the accessor before disabling the frame. Tokens are not stored, logged, placed in DOM attributes or sent to any product server. No getter is installed in normal tabs or nested documents. This does not isolate a token from other scripts of the same site origin, including a same-origin child reading its parent document. Chrome’s cookies permission can technically reach other cookies on granted hosts; the one-cookie restriction is enforced by this implementation, not by the browser permission itself.

Site access is requested when opening or selecting a social. Optional host permissions are not grants for every site. Stored legacy custom URLs remain usable, with former full-site YouTube panels migrated to Shorts. New selections are Facebook, Instagram, Threads, TikTok, Reddit, YouTube Shorts and X. Reddit requests `https://www.reddit.com/*`, `https://reddit.com/*` and optional `cookies` access; Shorts retains `https://www.youtube.com/*` for native site requests. X requests only https://x.com/* and optional cookies. Other socials do not request cookie access. X does not request api.x.com.

TikTok requests `https://*.tiktok.com/*` because its player loads video from additional TikTok subdomains. Access to `www.tiktok.com` alone can load the page while video requests fail with HTTP 403 due to the embedded request's cookie context. Existing TikTok panels with that older grant keep their position and preferences but show Open until you approve the broader TikTok access. Permission denial leaves the layout intact. Other sites retain their exact host grants. This does not add cookie-reading APIs or expand frame-header rules to video servers.

The extension removes X-Frame-Options and the entire CSP response header for network subframe documents matching an enabled panel's exact origin in its registered workspace tab. This includes matching nested iframes, not only the direct frames eligible for script injection. Removing CSP also removes its script/connect restrictions, reducing protection inside those documents; it is not limited to frame-ancestors. Normal tabs and nonmatching origins are outside these rules. Service Worker-generated responses may bypass network rules. For Facebook, Instagram and Threads, a workspace subframe rule also sets Sec-Fetch-Dest to document for compatibility; this does not turn the iframe into a first-party tab.

Scripts control scrolling and activate native appearance controls only in registered frames, with the fixed CSRF fallbacks described above. They do not collect posts, DMs or passwords, persist cookie values, or automate likes/comments/posts. Social apps own their native visual preferences; the extension does not write fabricated preference values or force their palette. Social sites still connect to their own services. There is no product server or analytics. The bundled Ubuntu fonts do not make requests to Google.

Threads homepage panels also load ahead through their native pagination. After site access is granted, a document-start MAIN-world helper recognizes the current 4000px viewport observer and uses the panel's own document with a 6000px forward margin. An implicit cross-origin iframe root can ignore margins; the local document makes the preload distance effective. Other observer configurations, routes, normal tabs and non-extension frames retain native behavior. Threads handles requests and its loading/end/error checks. This can load extra content before you read it and still cannot guarantee uninterrupted scrolling on a slow connection. Site changes that no longer match the known configuration fall back to native loading.

Layout and URLs use chrome.storage.local; runtime sessions use extension session storage. Panel Back retains up to 50 same-origin URLs per panel in that session, including query strings such as YouTube searches. These are not sent to a product service and are cleared with the runtime panel/session. This is not a backup of site drafts or history. A comment/chat or modal keeps its own scrolling. The background feed resumes sync when the modal closes. Virtualized cell replacement, shrinking and layout anchoring reset measured offsets without cancelling the remaining wheel gesture; root changes still discard queued movement. A Connected indicator confirms extension communication with a frame; it does not certify that the site has loaded posts or passed its own access checks.

## Releases

One branch: `main`. GitHub Actions runs extension checks/tests/packaging and website build/tests in separate jobs on pushes and pull requests. Cloudflare Pages Git integration handles website deployments separately when configured; see the website deployment guide. GitHub Releases carry Beta prereleases and Stable releases. GitHub Stable is published before Chrome Web Store; it remains a manual unpacked installation. No nightly branch, update server or Chrome Web Store publishing is configured.

The numeric version in package.json, package-lock.json and the manifest must agree. The manifest's version_name is the display/release name. First Beta: numeric `0.6.0`, display `0.6.0-beta.1`, tag `v0.6.0-beta.1`. Beta 2 uses numeric `0.6.1` and display `0.6.1-beta.2`. First Stable uses numeric/display `1.0.0` and tag `v1.0.0`. Each later published build increases the numeric version.

1. Update the versions, run the checks and commit. Wait for CI on that exact commit.
2. Create an annotated tag matching version_name, then create a clean detached worktree of that tag.
3. Run `npm ci` and `npm run release:pack` there. The ZIP has manifest.json at its root, runtime files, icons, fonts and required licenses; the source logo and development files are excluded. Packaging rejects missing relative JavaScript imports. Its timestamps are fixed for repeatable packaging.
4. Push that tag and create a GitHub prerelease for Beta, or a normal release for Stable. Attach only the ZIP and its .sha256 from the tagged worktree. Link to the matching public source tag.
5. Download the assets again, verify SHA-256, extract to a stable directory and Load unpacked. For updates, overwrite that same directory and Reload, preserving the Chrome profile and extension ID.

Use [the latest release](https://github.com/tqdat410/3fingers/releases/latest) for Stable and [all releases](https://github.com/tqdat410/3fingers/releases) for Beta history. A prerelease is not the stable latest release. Never publish generated diagnostics, private account screenshots, secrets or local development history.

Before submitting to Chrome Web Store, follow [Store preparation](store-submission.md). The user-facing data inventory is in the [privacy policy](privacy-policy.md). GitHub Stable does not certify Store approval or signed-in long-session performance. Keep outstanding Store/security/QA work visible in release notes; these documents do not mean a Store listing has been submitted or approved.
